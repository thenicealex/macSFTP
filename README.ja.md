# macSFTP

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語** | [한국어](README.ko.md)

Rust で書かれたネイティブな macOS 用 SFTP クライアントです。macSFTP はローカルとリモートのファイルを 1 つのウィンドウに並べます。上部に接続タブ、中央に 2 つのファイルペイン、下部に転送ドロワーがあります。UI は GPUI と GPUI Base で描画し、SSH と SFTP は `russh` / `russh-sftp` を Tokio 上で動かします。

macSFTP はプレリリース段階です。ローカル利用向けの未署名アプリバンドルをビルドでき、公開リリースはソースのみを提供します。Developer ID 署名、公証、自動アップデート、SFTP 以外のプロトコルは現在の対象外です。

## 機能

**接続とセキュリティ**

- 複数ウィンドウ。各ウィンドウは独立した接続タブを持ちます
- 保存済みプロファイルと、プロファイル一覧に入らない一時的な接続
- パスワード、複数ラウンドの keyboard-interactive、SSH agent、秘密鍵による認証
- Ed25519、ECDSA、RSA-SHA2 のクライアント鍵。RSA の直接署名には AWS-LC を使用
- 保存済みプロファイルによるシングルホップのジャンプホストと、明示的な OpenSSH 形式の `ProxyCommand`
- OpenSSH 互換のホスト鍵検証（`known_hosts` のサブセット）
- 未知のホストは確認を求め、保存済みの鍵と一致しない場合は接続を遮断
- パスワードと秘密鍵のパスフレーズは macOS Keychain に保存し、メモリ上は短命なコピーのみ

**ファイル閲覧**

- ローカル / リモートペイン。戻る・進むの履歴、パンくず、パスへの移動に対応
- 仮想化されたファイル一覧。1 万件でも操作感を維持
- 絞り込み、並べ替え、複数選択、Finder 風のタイプセレクト、隠しファイル表示
- 名前変更、新規フォルダ、削除、パスのコピー。ローカル側では Finder で表示も可能
- ファイル一覧と入力欄のコンテキストメニューはネイティブの AppKit メニューで表示

**転送**

- ディレクトリのアップロード / ダウンロードをプランとしてモデル化し、進捗を逐次公開
- パイプライン読み取りによるダウンロード: 同時 16 リクエスト、256 KiB チャンク、プランごとに最大 4 ジョブ、全体で最大 6 ジョブ
- 競合処理。プラン単位の「すべてに適用」、キャンセル、再試行に対応
- プロセス全体で共有される転送ドロワー。すべてのウィンドウから同じキューを表示
- メタデータ保持の失敗は警告として表示し、転送済みデータは成功のまま扱う
- シンボリックリンクはリンク自体をコピーし、既定では参照先をたどらない

**リモート編集**

- リモートファイルを開くと（ダブルクリック、`↩`、コンテキストメニュー）、一時コピーをエディタで開きます
- 変更したコピーには `●` が付き、アップロードは明示的な操作からだけ始まります
- **Upload Changes** を明示的に実行し、アップロード前に最新のリモートメタデータを確認
- リモート側が変わっていれば競合の判断を求め、**Compare Changes…** を利用可能
- ワイルドカード / 拡張子ごとのエディタ指定と、ステータスバーでの編集状態表示

**インターフェース**

- One Light と One Dark の 2 テーマ。システムに追従するか明示的に固定
- アプリレベルの操作はコマンドパレットから実行可能。ウィンドウとアプリのライフサイクルコマンドは標準のメニュー位置に残ります
- ファイル一覧、モーダル、タブ、設定をキーボードで操作可能
- 転送の進捗、エラー、空の状態には次にすべきことを明示

## サーバーへの接続

`⌘T` で接続タブを追加し、サーバーペインの **Connect…** からサーバー、ポート、ユーザー名、サインイン方法を入力します。**Enter Details** を選んだ場合、接続は一時的なままで、プロファイルとして保存されず認証情報も保存されません。ただし接続先は Recent Connections に記録されます。プロファイルとして保存するには保存済みプロファイルを選ぶか、**Manage Connections…** を開きます。プロファイルの作成と編集は **Settings → Saved Connections** で行います。

接続に成功すると、サーバーペインの **Recent Connections** に最大 6 件まで記録されます。表示名、`user@host:port`、前回のリモートフォルダが並びます。保存済みプロファイルに使える認証情報が残っていれば選ぶだけで再接続し、そうでなければ入力済みの接続フォームが開きます。

未知のホストへの初回接続では、サーバーアドレス、鍵の種類、SHA-256 フィンガープリント、保存先の `known_hosts` を表示します。主操作 **Trust and Save** は明示的な判断です。保存済みの鍵と一致しない場合は接続が遮断されます。

## リモート編集の流れ

リモート編集は明示的です。エディタで保存してもアップロードは始まりません。

1. リモートファイルを開きます（ダブルクリック、`↩`、コンテキストメニュー）。macSFTP が一時コピーをダウンロードし、エディタで開きます。
2. コピーを編集して保存します。一時コピーが変わると、一覧に `●` が表示されます。
3. リモートファイルを選び直し、ステータスバーの **Upload Changes** か **Upload Edited File**（`⌘⇧U`）を実行します。
4. macSFTP が最新のリモートメタデータを読みます。サーバー側が変わっていれば、上書き前に確認し **Compare Changes…** を提示します。
5. 失敗した場合、ローカルコピーは保持され、再試行できます。

**Compare Changes…** は毎回リモートファイルを専用ディレクトリへ取得し直すため、古いスナップショットが現在のサーバー版として扱われることはありません。タブやウィンドウを閉じると編集セッションが終了し、一時ディレクトリが削除されます。

## 動作環境

- macOS 13 以降。検証済みのアーキテクチャは arm64 で、ツールチェーンがそのターゲットを固定し、リリース記録もそれを対象にしています
- Xcode
- Rust `1.96.1`（`rust-toolchain.toml` で固定）、`rustfmt` と `clippy`
- アーキテクチャ検査用の Python `3.11` 以降（CI は `3.13`）
- 実セッションテスト用の `/usr/sbin/sshd`、`ssh-keygen`、`ssh-keyscan`

Metal シェーダーはアプリ起動時にコンパイルされるため、macSFTP のビルドに Metal Toolchain コンポーネントは不要です。

## ビルドと実行

```bash
cargo run                 # ワークスペースから直接実行
bash scripts/check.sh     # fmt、アーキテクチャ、ログ安全性、テスト、clippy
bash scripts/build_app.sh # build/macSFTP.app に未署名バンドルを生成
```

`open build/macSFTP.app` でアプリを開けます。署名がないためローカルテスト向けで、配布には Developer ID 署名と公証が必要です。

`check.sh` は CI と同じ整形、アーキテクチャ、ログ安全性、テスト、Clippy のゲートを実行します。SFTP 統合テストはローカルの `sshd` に接続します。ローカルで利用できない場合は明確なメッセージ付きでスキップされますが、CI では `MACSFTP_REQUIRE_SSHD=1` が設定されているためスキップせず失敗します。`Cargo.toml`、`Cargo.lock`、ベンダーコードを変更した場合は次も実行してください。

```bash
cargo deny --locked check advisories bans licenses sources
```

## データの保存場所

| パス | 内容 |
| --- | --- |
| `~/Library/Application Support/macSFTP/config.json` | 環境設定 |
| `~/Library/Application Support/macSFTP/profiles.json` | 保存済み接続プロファイル（機密値なし） |
| `~/Library/Application Support/macSFTP/known_hosts` | 信頼したホスト鍵 |
| `~/Library/Application Support/macSFTP/session.json` | ウィンドウとタブの復元情報 |
| `~/Library/Application Support/macSFTP/recents.json` | 最近の接続先 |
| `~/Library/Application Support/macSFTP/edits/` | リモート編集用の一時コピー |
| `~/Library/Application Support/macSFTP/residual_temp.json` | 中断された転送が残した一時ファイルの記録 |
| `~/Library/Logs/macSFTP/macsftp.log` | 診断ログ |

パスワードと秘密鍵のパスフレーズは macOS Keychain に保存され、プロファイルは参照のみを持ちます。コマンドパレットの **Show Logs** でログフォルダを開けます。ログは秘密値、秘密鍵の完全なパス、ProxyCommand の内容を伏せたうえで書き出されます。

## アーキテクチャ

ワークスペースは責務ごとに分割されています。

| Crate | 責務 |
| --- | --- |
| `macsftp-core` | 純粋なモデルと状態機械 |
| `macsftp-ui` | プロジェクト固有の GPUI Base コントロール、テーマ、表示層 |
| `macsftp-native-menu` | 入力欄とファイルペインのコンテキストメニュー向けの、分離された macOS AppKit プレゼンター |
| `macsftp-app` | ウィンドウ、アクション、UI 状態、イベント調整 |
| `macsftp-sftp` | Tokio runtime、russh アダプター、セッション、転送 |
| `macsftp-storage` | プロファイル、known hosts、Keychain 参照、マイグレーション |
| `macsftp-platform` | macOS とローカルファイルシステムの境界 |
| `macsftp-test-support` | 共有の統合テスト用フィクスチャ |

GPUI と Tokio は有界の command / event チャネルで通信し、ネットワーク処理は UI スレッドの外で動きます。閉じたタブや置き換えられたセッションからの古いイベントは、状態を変更する前に `core` で破棄されます。依存関係の規則、ランタイムモデル、UI の制約は [`docs/architecture.md`](docs/architecture.md) に記載しています。

本番の SFTP runtime は実際の SSH バックエンドを対象にビルドされ、モックの actor とコンストラクタはクレートのテスト用にのみコンパイルされます。

## 対象外

FTP、WebDAV、S3、内蔵ターミナル、ディレクトリ同期、マルチホップのジャンプホスト、`~/.ssh/config` の完全な解析、起動をまたぐ転送の復元、App Store 配布、公証済みリリース、終了後も続くバックグラウンド転送。

## セキュリティ

認証情報、秘密鍵の内容、ホストフィンガープリントなどの機密データは公開 issue の外に留めてください。非公開の報告手順は [`SECURITY.md`](SECURITY.md) を参照してください。
